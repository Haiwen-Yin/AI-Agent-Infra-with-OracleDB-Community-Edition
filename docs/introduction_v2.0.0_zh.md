# Oracle AI 数据库记忆系统 v2.0.0

> **统一 AI 智能体记忆系统** — 基于知识图谱、多智能体协作、任务规划、Harness 模板引擎与 Web 可视化，构建于 Oracle 23ai 之上。

**版本**: v2.0.0 | **日期**: 2026-05-15 | **作者**: 尹海文 | **许可**: Apache License 2.0

---

## 一、项目概述

Oracle AI 数据库记忆系统是一个面向 AI 智能体（Agent）的企业级记忆管理平台，旨在为 AI 应用提供结构化的长期记忆、知识图谱、多智能体协作与任务编排能力。系统以 Oracle 23ai 数据库为核心存储，利用其原生 JSON、向量检索、属性图（Property Graph）和 JSON-Relational Duality View 等高级特性，实现了一个统一、高效、可扩展的智能体记忆基础设施。

**v2.0.0 是一次完全重写**，与 v1.x 不兼容，无升级路径，需全新部署。

---

## 二、为什么重写？— v1.x 的痛点与 v2.0 的方案

| v1.x 痛点 | 影响 | v2.0 方案 | 效果 |
|-----------|------|----------|------|
| 5 张独立实体表 | 数据冗余、查询不一致、无法跨类型关联 | 单一 ENTITIES 表 + ENTITY_TYPE 区分符 | 一个数据源，统一查询 |
| 3 张独立关系表 | 同一概念 3 种表示方式 | 单一 ENTITY_EDGES 表 | 统一边类型命名空间 |
| SQLcl 子进程执行每次 DB 操作 | 超时 90 秒以上 | Python oracledb 驱动 + 连接池 | 查询 ~20ms，**加速 4500 倍** |
| 15+ 零散 SQL 脚本 | 无部署顺序、依赖断裂、不可重入 | 4 阶段有序部署脚本 | 幂等、可重复、可追溯 |
| 934 行 SKILL.md + 12 个散落文档 | 无法导航、内容过时、重复 | 200 行 SKILL.md + 8 个专题文档 | 可维护、可导航 |
| 知识/记忆两个独立属性图 | 无法跨类型遍历 | 单一 ORACLE_MEMORY_GRAPH | 跨类型图遍历 |
| memory_system_users 表 | 非标准、无角色体系 | SYSTEM_USERS + 角色分级 | 标准 RBAC 访问控制 |

## 三、核心架构

### 3.1 统一实体模型

v2.0 将 v1.x 的 5 张碎片化实体表合并为一张 **ENTITIES** 表，通过 `ENTITY_TYPE` 区分不同类型：

```
ENTITIES（统一实体表）
  ├── MEMORY          — 短期智能体记忆（替代 MEMORIES + MEMORY_NODES）
  ├── KNOWLEDGE       — 长期验证知识（替代 KNOWLEDGE_CONCEPTS）
  ├── TASK_OUTPUT     — 任务执行输出
  ├── EXPERIENCE      — 学习经验与启发式规则
  └── HARNESS_TEMPLATE — 可复用智能体执行蓝图
```

**核心优势**：
- **跨类型关联**：记忆可直接关联到知识（如“记忆 → 知识”推导链）
- **统一查询**：一次查询所有类型，或按 ENTITY_TYPE 过滤
- **一致性**：所有实体共享可见性、标签、元数据体系
- **零冗余**：消除 MEMORIES 与 MEMORY_NODES 的数据重复

### 3.2 统一边模型

**ENTITY_EDGES** 替代 v1.x 的 3 张关系表，定义 10 种统一边类型：

| 边类型 | 含义 | 边类型 | 含义 |
|--------|------|--------|------|
| DEPENDS_ON | 依赖 | ENABLES | 使能 |
| RELATED_TO | 相关 | PREVENTS | 阻碍 |
| DERIVED_FROM | 推导来源 | SIMILAR_TO | 相似 |
| CAUSES | 因果 | EVOLVED_FROM | 演化来源 |
| CONTRADICTS | 矛盾 | SUPPORTS | 支持 |

每条边携带 **STRENGTH**（0-2，强度）和 **CONFIDENCE**（0-1，置信度），支持加权图遍历。

### 3.3 辅助表体系

| 表名 | 用途 |
|------|------|
| KNOWLEDGE_META | 知识实体扩展元数据（来源、验证、版本、置信度） |
| HARNESS_META | 模板版本、状态、变量、变更日志 |
| ENTITY_EMBEDDINGS | 语义向量嵌入 VECTOR(1024, FLOAT32) |
| AGENT_REGISTRY | 智能体身份、能力、权限 |
| AGENT_SESSION | 会话追踪与上下文快照 |
| ENTITY_ACCESS_LOG | 实体访问审计日志 |
| AGENT_PERMISSION_LOG | 权限变更审计 |
| AGENT_COLLABORATION | 跨智能体共享请求 |
| TASK_PLANS | 多步骤任务定义 |
| TASK_STEPS | 计划步骤与状态追踪 |
| TASK_CONTEXT_SNAPSHOTS | 断点/恢复快照 |
| TASK_TOOL_CALLS | 工具调用审计 |
| TASK_DEPENDENCIES | 跨计划依赖图 |
| TAGS / ENTITY_TAGS | 标签归一化体系 |
| SYSTEM_CONFIG | 系统配置 |
| SYSTEM_USERS | 系统用户与角色（USER/ADMIN/SYSTEM） |

### 3.4 属性图与对偶视图

- **ORACLE_MEMORY_GRAPH**：统一属性图，替代 v1.x 的两个独立图，支持 SQL PGQ 语法跨类型图遍历
- **MEMORY_DV / KNOWLEDGE_DV**：JSON-Relational Duality Views，提供实体 + 边的 JSON 视图

## 四、4 阶段 SQL 部署

v1.x 的 15+ 零散脚本整合为 4 个有序部署阶段：

### Phase 1: `1_schema.sql` — 模式层
- 16 张表、25+ 索引、1 个属性图、2 个对偶视图
- `safe_ddl`/`safe_idx` 辅助函数确保幂等重跑
- `GENERATED BY DEFAULT AS IDENTITY` 自增主键
- 原生 JSON 列（TAGS、METADATA、ACCESSIBLE_TO、PROPERTIES）
- 所有枚举列加 CHECK 约束，外键 ON DELETE CASCADE
- 种子数据：SYSTEM_CONFIG（版本 2.0.0）、SYSTEM_USERS（admin 账户）

### Phase 2: `2_api.sql` — PL/SQL API 层
4 个 PL/SQL 包：

| 包名 | 功能 |
|------|------|
| MEMORY_FUSION_ENGINE | 合并相似记忆、提取知识、衰减优先级 |
| KNOWLEDGE_BASE_API | 验证/废弃/版本化知识概念、血统查询 |
| AGENT_PERMISSION_MANAGER | 访问控制、会话清理、协作处理 |
| SESSION_CLEANUP | 清除日志、归档实体、更新标签计数 |

### Phase 3: `3_jobs.sql` — 调度层
7 个自动化调度作业：

| 作业 | 调度 | 功能 |
|------|------|------|
| MEMORY_FUSION_JOB | 每天 02:00 | 融合相似记忆 + 优先级衰减 |
| KNOWLEDGE_EXTRACTION_JOB | 每天 03:00 | 从记忆模式提取知识 |
| SESSION_CLEANUP_JOB | 每 30 分钟 | 清理过期会话 |
| ACCESS_LOG_PURGE_JOB | 每周日 04:00 | 清除 90 天以上日志 |
| TAG_COUNT_UPDATE_JOB | 每天 01:00 | 更新标签使用计数 |
| COLLAB_EXPIRY_JOB | 每天 00:30 | 过期协作请求 |
| ENTITY_ARCHIVE_JOB | 每周日 05:00 | 归档 180 天以上低优先级记忆 |

### Phase 4: `4_harness_templates.sql` — Harness 模板层
- 创建 HARNESS_META 表
- 扩展 CK_ENTITY_TYPE 约束增加 HARNESS_TEMPLATE
- 种子化 5 个内置模板（状态：PUBLISHED）

## 五、Python API 库

### 5.1 技术栈

| 指标 | v1.x (SQLcl) | v2.0 (oracledb) | 提升 |
|------|-------------|-----------------|------|
| 查询延迟 | 90+ 秒 | ~20ms | **4500x** |
| 连接模型 | 每次查询启动新进程 | 连接池 (min=2, max=5) | 复用 |
| 错误处理 | 解析 stdout | Python 异常 | 类型安全 |
| 参数绑定 | 字符串拼接 | `:param` 绑定语法 | 防注入 |
| LOB 处理 | 手动 | `fetch_lobs = False` | 自动化 |

### 5.2 模块结构（8 个模块）

| 模块 | 功能 |
|------|------|
| `config.py` | 统一配置数据类，支持环境变量覆盖 |
| `connection.py` | oracledb 连接池管理（延迟初始化、线程安全） |
| `memory_api.py` | 记忆 CRUD（ENTITIES, ENTITY_TYPE=&apos;MEMORY&apos;） |
| `knowledge_api.py` | 知识 CRUD + 图操作（ENTITIES + KNOWLEDGE_META + ENTITY_EDGES） |
| `agent_api.py` | 智能体注册、会话、协作、访问日志 |
| `task_plan_api.py` | 任务计划、步骤、快照、工具调用、依赖 |
| `security.py` | 数据脱敏、可逆加密、密码哈希 |
| `harness_api.py` | 模板 CRUD、实例化、派生、验证（12 个公开函数） |

### 5.3 代码示例

```python
from scripts.lib.memory_api import create_memory, get_memory, search_memories
from scripts.lib.knowledge_api import create_concept, create_relationship
from scripts.lib.agent_api import register_agent, create_session
from scripts.lib.harness_api import create_template, instantiate_template, derive_template

# 创建记忆
mid = create_memory("会议纪要", "讨论了 v2.0 架构方案", category="meeting")

# 创建知识概念
kid = create_concept("统一架构模式", "principle",
                     description="单一 ENTITIES 表", confidence=0.95)

# 建立关联（记忆 → 知识推导链）
eid = create_relationship(mid, kid, "DERIVED_FROM", strength=0.9)

# 注册智能体
register_agent("agent-1", "研究智能体", capabilities=["read", "write"])

# 创建并实例化 Harness 模板
tpl_id = create_template("分析师",
                         prompt_templates={"system": "你是一个{role}..."},
                         tool_sets=["knowledge_tools", "memory_tools"],
                         variables={"role": "分析师"})
config = instantiate_template(tpl_id, variables={"role": "数据科学家"})
```

### 5.4 设计模式

- 所有查询使用绑定变量（防 SQL 注入）
- `INSERT...RETURNING` 返回自增 ID
- `execute_query` 返回 `List[Dict[str, Any]]`（列名作键）
- `MERGE INTO` 实现幂等注册
- `_sanitize_decimals()` 处理 oracledb 返回的 `decimal.Decimal`
- `_fix_encoding()` 修正 oracledb thin 模式的 UTF-8 双重编码

## 六、Harness 模板系统

Harness 模板是 v2.0 新增的核心特性，为智能体提供可复用的执行蓝图。

### 6.1 模板结构

每个模板以 `ENTITY_TYPE=&apos;HARNESS_TEMPLATE&apos;` 存储在 ENTITIES 表中，配置存储在 METADATA JSON 列：

```
METADATA JSON
  ├── prompt_templates    — 参数化提示模板（支持 {variable} 插槽替换）
  ├── tool_bindings       — 工具名称 + 访问权限对
  ├── memory_access       — 短期/长期记忆、压缩、访问策略
  ├── guardrails          — 最大迭代次数、执行时间、内容审核、PII 过滤
  ├── evaluation          — 输出格式、质量阈值
  └── variables           — 默认变量值
```

### 6.2 关键能力

| 能力 | 说明 |
|------|------|
| **变量替换** | `{role}`、`{domain}` 等在实例化时解析替换 |
| **模板继承** | 子模板通过 `DERIVES_FROM` 边继承父模板，深度合并覆盖 |
| **5 个内置工具集** | memory_tools、knowledge_tools、agent_tools、security_tools、task_tools |
| **3 个护栏预设** | conservative（5次/60秒）、balanced（15次/300秒）、aggressive（50次/900秒） |
| **生命周期管理** | DRAFT → PUBLISHED → DEPRECATED → ARCHIVED（HARNESS_META 追踪） |
| **模板验证** | 检查提示完整性、变量一致性、工具重复、护栏合理性 |

### 6.3 内置模板

| 模板 | 类别 | 工具集 | 护栏预设 |
|------|------|--------|---------|
| Research Analyst（研究分析师） | research | knowledge_tools + memory_tools | balanced |
| Code Assistant（代码助手） | development | knowledge_tools + task_tools | balanced |
| Data Analyst（数据分析师） | analytics | knowledge_tools + memory_tools | conservative |
| Task Planner（任务规划器） | orchestration | task_tools + agent_tools | balanced |
| Security Auditor（安全审计员） | security | security_tools + knowledge_tools | conservative |

### 6.4 Python API（12 个函数）

| 函数 | 功能 |
|------|------|
| `create_template()` | 创建模板（提示、工具、护栏、变量） |
| `get_template()` | 获取模板完整元数据 + HARNESS_META |
| `list_templates()` | 列表（支持类别/状态过滤） |
| `update_template()` | 更新实体字段和模板状态 |
| `delete_template()` | 删除模板 + HARNESS_META + 关联边 |
| `resolve_template()` | 递归解析继承链（深度合并） |
| `instantiate_template()` | 解析 + 变量替换 + 覆盖 → 运行时配置 |
| `derive_template()` | 从父模板创建子模板 |
| `validate_template()` | 完整性和一致性检查 |
| `get_template_lineage()` | 获取继承谱系 |
| `publish_template()` | 发布模板（DRAFT → PUBLISHED） |
| `deprecate_template()` | 废弃模板（附原因） |

## 七、安全模块

### 7.1 数据脱敏（DataMaskingService）

- **7 种模式类型**：email、phone、credit_card、ssn、api_key、ip_address、jwt_token
- **4 种上下文级别**：LOGGING、DEBUGGING、ANALYTICS、SHARING
- 确定性匹配顺序（credit_card 优先于 phone，避免误匹配）
- 敏感字典键无正则匹配时返回 `***MASKED***` 兜底

### 7.2 可逆加密（ReversibleEncryption）

- PBKDF2 密钥派生 + XOR 加密
- 长度前缀编码（替代零字节填充）
- 安全密钥轮换：先全部解密，再用新密钥重新加密

### 7.3 密码哈希

- PBKDF2-HMAC-SHA256，可配置迭代次数（默认 100,000 次）

## 八、Web 可视化系统

### 8.1 四页面仪表板

| 页面 | 路由 | 功能 |
|------|------|------|
| **知识图谱** | `/knowledge` | vis.js 交互式图，节点点击查看详情，展示 KNOWLEDGE 实体及关系 |
| **记忆内容** | `/memory` | vis.js 交互式图，展示 MEMORY 实体及连接 |
| **智能体协作** | `/agents` | 3 标签页仪表板：智能体注册表（状态/权限徽章）、活跃会话、协作请求 |
| **任务计划** | `/tasks` | 状态过滤下拉框、关键词搜索、手风琴式计划列表、可展开步骤表格、进度条 |

### 8.2 特性

- **中英双语 UI**：一键切换，localStorage 持久化
- **会话认证**：SYSTEM_USERS 凭据登录，可配置超时自动登出
- **UTF-8 编码修正**：`_fix_encoding()` 自动检测并修正 oracledb thin 模式返回的双重编码中文
- **请求异常隔离**：`_do_GET` 异常包装器，单个请求失败不影响服务器运行
- **类型安全序列化**：`_sanitize_val()` 处理 Decimal/datetime，`json.dumps(default=str)` 兜底

### 8.3 服务器控制脚本

```bash
./start_web_server.sh start     # 启动（守护进程模式）
./start_web_server.sh stop      # 停止（优雅 → 10秒超时 → 强制）
./start_web_server.sh restart   # 重启
./start_web_server.sh status    # 状态 + 配置摘要
./start_web_server.sh config    # 完整配置信息
./start_web_server.sh log       # 查看最近 50 行日志
```

特性：
- 自动检测 Python 3.14（跳过系统 Python 3.6.8）
- 从 `config.json` 读取配置
- 环境变量覆盖（`MEMORY_DB_USER` 等）
- PID 文件管理（`/tmp/oracle_memory_viz.pid`）
- 端口就绪检测（45 秒超时）
- 启动后显示所有页面入口 URL

## 十、开发过程中修复的关键 Bug

| Bug | 修复方案 |
|------|------|
| oracledb 返回 `decimal.Decimal` 无法 JSON 序列化 | 添加 `_sanitize_decimals()` 和 `_sanitize_val()` 自动转换 |
| oracledb thin 模式双重编码 UTF-8 中文 | 添加 `_fix_encoding()` 智能检测 CJK vs Latin-1 范围字符 |
| viz_server 任何请求崩溃导致服务器死亡 | `do_GET` → `_do_GET` 异常包装器隔离单请求失败 |
| f-string 变量名错误 `{sess_ttl}` | 修正为 `{SESS_TTL}` |
| 任务页面缺少 `<script>` 标签 | JS 代码添加 script 包装 |
| 手机号正则匹配到信用卡号 | 调整模式匹配顺序（credit_card 优先） |
| Oracle 保留字 `:desc` 作为绑定变量 | 重命名为 `:adesc` |
| `SYSTIMESTAMP` 作为绑定变量传入 | 改为 SQL 字面量 |
| 密钥轮换损坏密文 | 先全部解密，再用新密钥重新加密 |
| 可逆加密零字节填充问题 | 改用长度前缀编码 |
