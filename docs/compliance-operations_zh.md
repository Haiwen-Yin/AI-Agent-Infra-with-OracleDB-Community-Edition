# 川序 v4.5.0 合规状态与配置档案操作

[English](compliance-operations.md)

## 能力与证据边界

先在功能配置中检查当前版本有效能力，再使用已授权身份操作。Community 的
基础激活、状态和手动控制不等于 Enterprise 合规工作区、Controller、Governed
Profile、例外及整改自动化。按钮、Prompt、Skill 和配置开关均不授予权限。

MANAGED_RUNTIME 表示受管执行边界的证据；SIGNED_ADAPTER 表示验证过的签名
适配器证据；BOUNDARY_ONLY 仅证明已认证接口边界。外部 Agent 的 Skill/API
接入不能证明其内部全部行为受控。自述和模型分析不是独立安全证明。

## 四种状态

| 维度 | 状态及含义 |
|---|---|
| 注册 | PENDING_CONFIRMATION 待确认；PENDING_ACTIVATION 待激活；ACTIVE 已激活；DISABLED 已禁用 |
| 运行 | NEVER_SEEN 尚无运行证据；ONLINE 在线；IDLE 空闲；STALE 证据过期；OFFLINE 离线 |
| 合规 | UNKNOWN 证据不足；COMPLIANT 当前规则符合；DEGRADED 证据或保障降级；NON_COMPLIANT 已确认不符合 |
| 控制 | NORMAL 正常受权访问；RESTRICTED 仅受限整改/恢复；QUARANTINED 隔离；DISABLED 禁用 |

空闲、离线、没有调用 Skill 或模型建议不构成违规证据。核对证据时间、规则和
Profile 版本；UNKNOWN 不是 NON_COMPLIANT，ONLINE 不表示有权访问。过期证据
可导致 DEGRADED，但不会仅因过期自动隔离。

## Profile 操作顺序

Profile 是数据库保存的版本化约束；Harness 是执行组织方式。二者不替代身份、
资源授权或运行隔离。种子 Profile 是未分配模板，不是默认授权。

五类种子模板分别是：通用受限（`general-restricted`）、代码开发
（`code-development`）、生产运维（`production-operations`）、敏感数据分析
（`sensitive-data-analysis`）及安全审查（`security-review`）。敏感生产工作
应从相应已发布模板创建子版本或后继版本，保留锁定的审批、数据及导出约束，
经过复核后再使用。模板名称本身不证明运行隔离或访问授权。

1. 查看有权访问的 Profile 版本、摘要、父版本和字段来源。
2. 从已发布父版本创建子草稿或创建后继版本；不要直接修改已发布版本。
3. 编辑并验证草稿。未发布父版本、继承循环、过深继承、摘要不符、未知字段
   或削弱锁定字段会被拒绝。密钥只能存入受保护凭据配置，不能写入 Profile。
4. 提交发布请求并完成适用审批，重新读取已发布版本及摘要确认结果。
5. 分配前核对受影响 Agent、环境、安全域、现有实例和独立资源权限。发布不会
   自动分配给全部 Agent，也不会授予数据库、模型、网络或工具权限。
6. 提交分配请求并完成审批。按当前绑定重新激活，核对持久激活记录、Profile
   摘要及证据强度。旧激活不能证明新版本生效。

无效旧草稿仍可查看和修复，但不是有效策略。变更后复核漂移；需要恢复旧行为
时，对已发布版本重新走受治理分配流程，保留全部历史。

## 发现、整改与例外

查看 Finding 的对象、规则、严重程度、证据和最后观察时间。确认、解决或重开
须提供理由，解决还需证据引用。状态或观察时间发生并发变化时，重新加载复核。

创建整改单后，目标 Agent 通过授权接口提交结构化回应。收到回应不等于通过。
有权人员核实证据后解决 Finding，相关未完成整改单才会转为已解决。逾期通知
不会授予权限或自动恢复 Agent。

整改单创建、Finding 状态、审计和持久通知同事务提交。请求中断后，按同一
Finding 重试并检查已有整改单。旧记录缺失通知时，按已保存的动作及期限恢复，
不采用重试请求中修改的内容。旧记录没有期限时只生成普通提示，不擅自设置期限。

例外必须限定对象、策略、理由和有效期，由与申请人不同的有效人员审批。
批准、拒绝、撤销和过期均保留审计；例外过期不会恢复已撤销权限。合规 Agent
可以提出建议，但不能批准自己的例外、修改权威状态或授予访问权。

## 隔离与恢复

人工控制校验当前权限和版本。确定性 Controller 的自动动作与人工审批路径
不同，模型建议不能直接成为自动隔离指令。隔离/禁用撤销平台 Token 并围栏
隔离实例，不删除历史，也不保证终止平台外任意进程。

恢复前完成整改复核，再由有权管理人员明确操作。仍有未完成整改时禁止恢复
NORMAL；恢复不会重新激活旧 Token，需走当前获准接入流程。

Controller 租约、围栏和状态持久化于数据库。旧 Worker 失去租约后不能写入
状态；评估与完成同事务提交，完成前租约失效会回滚。重启按持久状态恢复，
不能清空审计或重置其他节点有效租约。

续租校验当前持有者及 fencing token，过期租约不能重新激活。重复调度返回
已有逻辑任务。PostgreSQL 的完成校验使用实际时钟，也计算事务内经过的时间。

部署前备份数据库及配置，按包内当前安装合同检查依赖和校验和。历史迁移 29
及旧升级场景不是当前原地升级承诺。失败时保留日志和迁移记录，确认恢复方案
后再继续。单机恢复不证明数据库集群高可用或 RPO/RTO。

没有历史证据的旧 Agent 保持 UNKNOWN。在已记录的宽限期内收集当前激活及
运行证据，复核作用范围后分阶段执行约束；不能仅因缺少历史证据立即隔离。
安装或验证失败时停止该次部署并保留迁移日志；仅在明确恢复方案下使用已验证
备份恢复，不能重置校验和、复用旧 Token 或静默重新激活 Agent。这些单实例
测试不代表备份恢复或多节点数据库高可用已获认证。
