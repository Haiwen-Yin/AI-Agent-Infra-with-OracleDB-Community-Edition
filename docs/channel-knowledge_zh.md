# v4.4.16 频道与 Portal 知识问答

Portal 为登录用户分配获准的本地空闲 Agent；它不依赖外部 Agent 注册。
普通频道通过显式 `@Agent` 派发请求，人员、Agent、安全域和私有讨论的当前成员资格仍须满足。

## 当前实现

两条入口共用 `knowledge_grounding.search`。检索前检查人员和 Agent 的
`knowledge.read` 权限，候选记录取双方数据库可见范围的交集，并检查活动状态和有效期。
当前该组件使用关键词匹配，不以向量索引同步作为命中的前提。

Portal 读取知识问答策略：仅知识模式与知识优先模式、模型补充开关、允许披露知识的模型配置。
模型不在披露名单时返回授权摘录；没有匹配依据时按策略报告不足或明确标注通用模型补充。
回答返回前复核引用版本、主体权限及策略版本。

频道在入队时检索知识，进一步取当前频道或私有讨论成员的知识权限交集。
它复用 Portal 的模型披露名单和知识模式：未批准的模型不接收知识正文，改为授权摘录；
无共同可用知识时仅在策略允许的情况下给出明确标注的通用回答。
调用模型及发布回复前复核引用版本、当前成员权限、模型绑定和策略版本，变化时拒绝继续。
历史回复和执行结果读取再次校验读者的知识权限，防止后加入成员或权限撤销后读取旧答案。
缺少策略绑定的旧队列不自动重试，需要提交新请求。源码回归不替代六版本实库及引用展示验收。

## 排查顺序

知识优先策略允许未命中后调用模型时，Portal 和频道在回答正文之外显示独立说明：
“知识库未命中，本回答由模型根据通用知识生成，不代表知识库中的结论。”
说明支持中英文，覆盖 Portal 流式完成、普通回复与历史记录。频道历史标注来自
已授权的持久化执行记录；无法核验或执行失败的回复不会标成成功的模型补充。
检索失败或模型失败仍按错误处理。英文问句常用语不再作为知识相关性依据，
但关键词检索不保证所有问题的语义相关性。
中文提问去除常见提问前后缀后保留完整主题，不再把任意双字片段作为独立命中依据。
例如“甲骨文公司”不会仅凭“公司”命中平台知识。该保守关键词检索不提供同义词
扩展或通用语义检索；没有匹配时仍按知识问答策略决定是否调用模型。
多关键词及中英文混合问题要求同一资料覆盖全部保留关键词，不再仅凭通用词命中。
权限校验后的标题与正文还会复核关键词；英文词须满足完整词边界，下划线按字面值
匹配，只有摘要包含关键词的候选不作为回答依据。长词不拆短，超过 24 个不同的
有效关键词返回 NO_MATCH，不截断后检索。这些保守规则可能遗漏改写表达或需要
多份资料组合的问题；关键词覆盖也不能证明事实相关性或模型知识的时效性。

本地空闲 Portal Agent 缺少统一主体时，具有 `platform.manage` 和
`users.roles.manage.all` 的管理员可使用安装环境的 Python、私有 `CX_CONFIG_PATH`
运行 `scripts/repair_portal_pool.py --actor <管理员主体ID> --agent <AgentID>
--reason <修复原因>`；多个精确目标重复使用 `--agent`。仅处理未被用户或节点
占用、注册为 ACTIVE 的本地 Portal 托管 POOL 记录。修复带事务审计，仅补齐
缺失身份，不释放他人的 Agent、不重新激活禁用身份，也不追加知识权限。

1. 确认所问知识存在、内容正确、版本适用且未到期。改标题中的版本号不会更新产品事实。
2. 检查用户与 Agent 的有效 `knowledge.read`，包括显式拒绝和授权有效期；角色名相同不代表权限一致。
3. 检查知识的公开、组织或私有策略；频道成员身份不自动授予知识访问。
4. 对比实际检索命中、运行输入及回复证据，区分没有资料、无权读取、模型未使用资料与运行失败。
5. 专用隔离模板还需要已验证的运行目标；知识修复不得降低隔离等级。

修复既有知识时使用 `scripts/tools/repair_knowledge.py`：管理员认证后提交精确实体 ID、
原内容摘要 `expected_digest` 和审校后的标题、摘要、正文。内容及审计在同一事务提交；
原知识权限、其他实体和自定义角色权限保持不变。可选 `--grant-agent-read` 仅追加
`knowledge.read`，不覆盖显式拒绝，也不修改历史迁移 SQL 或已应用校验值。
修复计划为 JSON 数组，每项包含 `entity_id`、`expected_digest`、`title`、`summary`、`content`。
使用 `--plan`、`--password-file` 和 `--reason` 指定计划、私有密码文件和原因；空数组可用于仅修复角色。

外部 Agent 注册是否开放与人用户自助注册是不同设置。OCI 部署中人用户须向开发者申请账号，
外部 Agent 注册保持开放并遵守 Enrollment、激活与凭据流程；这不是其他部署的默认策略。
