# Architecture - Oracle Memory System v2.0.0

## Unified Entity Model

v2.0 replaces 5 separate tables (MEMORIES, MEMORY_NODES, MEMORY_EDGES, MEMORY_RELATIONSHIPS, KNOWLEDGE_CONCEPTS) with 2 unified tables:

### ENTITIES
Single table with `ENTITY_TYPE` discriminator:
- **MEMORY**: Replaces MEMORIES + MEMORY_NODES. Fields: name, content, category, priority, status, tags, metadata, visibility, accessible_to
- **KNOWLEDGE**: Replaces KNOWLEDGE_CONCEPTS. Extended by KNOWLEDGE_META for source tracking, validation, versioning
- **TASK_OUTPUT**: Task execution results
- **EXPERIENCE**: Learned patterns and heuristics

### ENTITY_EDGES
Unified directed edge table replacing:
- MEMORY_EDGES (memory → memory links)
- MEMORY_RELATIONSHIPS (semantic relationships)
- KNOWLEDGE_GRAPH (concept relationships)

Edge types: DEPENDS_ON, RELATED_TO, DERIVED_FROM, CAUSES, ENABLES, PREVENTS, SIMILAR_TO, EVOLVED_FROM, CONTRADICTS, SUPPORTS

## Visibility Model

| Level | Behavior |
|-------|----------|
| PRIVATE | Only owner agent can access |
| SHARED | All registered agents can access |
| COLLABORATIVE | Owner + agents listed in ACCESSIBLE_TO JSON array |

## Property Graph

Single `ORACLE_MEMORY_GRAPH` replaces v1's separate KNOWLEDGE_PROPERTY_GRAPH and MEMORY_PROPERTY_GRAPH.
Enables graph traversal queries via SQL PGQ syntax.

## JSON Duality Views

- **MEMORY_DV**: JSON read/write view for MEMORY-type entities with their edges
- **KNOWLEDGE_DV**: JSON read/write view for KNOWLEDGE-type entities with metadata and edges

## Design Decisions

1. **GENERATED BY DEFAULT AS IDENTITY** for all PKs (no explicit sequences needed for inserts)
2. **JSON columns** for TAGS, METADATA, ACCESSIBLE_TO, PROPERTIES, SOURCE_ENTITY_IDS
3. **CLOB** for CONTENT and RESULT fields (large text storage)
4. **VECTOR(1024, FLOAT32)** for embeddings (compatible with BGE-M3 model)
5. **ON DELETE CASCADE** on all foreign keys referencing ENTITIES
6. **CHECK constraints** on all enum-like columns for data integrity
